Quod 0.1.6: what a review of 0.1.5 found, and the compiler that the held-out tasks will measure.

## Install

As for [0.1.0](https://github.com/quod-lang/quod/releases/tag/v0.1.0): download the package for
your system, unpack it, and run `quod` from that folder (z3 4.12.1 is inside). On macOS, run
`xattr -d com.apple.quarantine quod z3` in the folder first. The MCP server:
`claude mcp add quod -- /path/to/quod mcp`, or see
[docs/mcp.md](https://github.com/quod-lang/quod/blob/main/docs/mcp.md). `Quod.Build`, attached, is a NuGet package:
see [its README](https://github.com/quod-lang/quod/blob/main/packaging/Quod.Build/README.md).

## Fixed

- **A `nat` parameter is checked at the public boundary, in Python and in C#.** A proved `ensures` could be false for a caller
  passing a negative integer, since the proofs rely on `n >= 0`. A list of `nat` counts as a quantified `requires`: it is checked with
  `--check-requires all` or, in C#, `QUOD_CHECK_REQUIRES`.
- **`--require-contracts` no longer refuses a fixed length of 2 or more:** a colour or a date is a record. Lengths 0 and 1 stay refused.
- **`Quod.Build`:**
  - changing an option now verifies again, without touching the file: `QuodRequireContracts` used to do nothing on a project already built;
  - under the MSBuild of Visual Studio, with the change of this version to its error handling, a failed proof always fails the build;
  - an error is no longer followed by MSB3073, which repeated the whole command;
  - a system with no `quod` in the package, such as an Intel Mac, says so instead of running the wrong binary;
  - the package no longer contains the sources of `dafny-complete`.
- `if (b == 0)` in generated C#, not `if (!(!(b == 0)))`.

## New

- **`--require-contracts` refuses a contract its `requires` already gives for an argument returned unchanged:** a `sort` of a list said to be sorted, where the
  function has nothing to do. `x * x == 25` still passes: a proof that a `requires` is too narrow is out of reach in general.
- **`quod contract FILE CASES --function NAME`** evaluates a contract, not the code, on given arguments and results.

- [`bench/verifbench/adequacy.py`](https://github.com/quod-lang/quod/blob/main/bench/verifbench/adequacy.py) measures whether a contract lets through a result the task forbids,
  on small inputs, without the code and without a judge. On the recorded base tasks it finds both proved and determined contracts that were wrong. With Haiku,
  18 of 18 contracts through the shell and 16 of 16 through MCP are sound, and 15 of 18 Dafny contracts, with 3 it cannot decide (an unbounded quantifier). All three shell
  contracts of `binary_search` are sound but not exact: they fix one index where the task allows any, so **the completeness check may push an agent to over-specify**, which the
  bench had not seen.
- [The protocol of the held-out tasks](https://github.com/quod-lang/quod/blob/main/bench/heldout.md) is complete: its main measure is soundness by execution. They will be run on this version.
