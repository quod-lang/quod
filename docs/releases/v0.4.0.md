Quod 0.4.0: the generated C# no longer uses `BigInteger`; a verdict no longer depends on the load of the machine; two modules that would collide in C# are refused. **Breaking for C# callers.**

## Install

As for [0.1.0](https://github.com/quod-lang/quod/releases/tag/v0.1.0): download the package for
your system, unpack it, and run `quod` from that folder (z3 4.12.1 is inside). On macOS, run
`xattr -d com.apple.quarantine quod z3` in the folder first. The MCP server:
`claude mcp add quod -- /path/to/quod mcp`, or see
[docs/mcp.md](https://github.com/quod-lang/quod/blob/main/docs/mcp.md). `Quod.Build`, attached, is a NuGet package:
see [its README](https://github.com/quod-lang/quod/blob/main/packaging/Quod.Build/README.md).

## Changed

- **C#: Quod's `int` and `nat` are a `long`, computed in `checked`.** No `BigInteger` is left in the generated code or in its signatures. Beyond about 9.2e18 an operation raises `OverflowException`: never a wrong result, but the proof, which is mathematical, did not foresee it. For a guarantee, use `i64` (or `i32`): the verifier then proves that no operation leaves the bounds. Callers that passed a `BigInteger` must change.
- **Limits are counts of z3 operations, not times** (review of 0.3.2, H3). A published solution failed 5 builds of 5 when run at once: the verdict depended on the load. Each limit in ms is now an rlimit of 4000 operations per ms; the time limit stays 4 times wider, against a check that never ends. `QUOD_RLIMIT_PER_MS` sets the rate. On 106 programs, no verdict changed but one proof that is now found (T7 next_permutation, quod-mcp #1). The whole-check budget (`--budget`) is still wall time.
- **Two modules that would be one C# class or file are refused** (review of 0.3.2, H1): `a_b` and `aB` both gave the class `AB`, and the code could contradict a proof.
- The reference and the specification say what `int` is in C# and point to `i64`.

## Known

Those of [0.3.2](https://github.com/quod-lang/quod/releases/tag/v0.3.2).

- **`int` in C# can overflow.** In the billing program with a discount shared in proportion, 4 orders of 235 raise `OverflowException` on `discount * net`, from a subtotal of tens of millions of euros. With `i64` the verifier refuses the product until `net` is bounded. A verifier warning for an `int` product that may exceed `long` is not done.
- The claims of T9 to T11 on time are not to be read as medians that mean anything: they were measured under a wall-time limit that depended on the load.
- Not run: macOS and Linux binaries (built by CI only).
