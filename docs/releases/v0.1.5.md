Quod 0.1.5: the C# backend, and what a review of 0.1.4 found.

## Install

As for [0.1.0](https://github.com/quod-lang/quod/releases/tag/v0.1.0): download the package for
your system, unpack it, and run `quod` from that folder (z3 4.12.1 is inside). On macOS, run
`xattr -d com.apple.quarantine quod z3` in the folder first. The MCP server:
`claude mcp add quod -- /path/to/quod mcp`, or see
[docs/mcp.md](https://github.com/quod-lang/quod/blob/main/docs/mcp.md).

## New

- **A C# backend.** `quod build file.quod --target csharp` writes a class that compiles with C# 7.3 and the
  standard library, for .NET Framework 4.7.2 as for .NET Core and later. `int` is `BigInteger`, `seq<T>` is
  `IReadOnlyList<T>`. A list of `int` or `long` is accepted as it is, without a copy. Equality is structural,
  division Euclidean, and a recursion too deep raises an exception instead of ending the process.
- **`Quod.Build`,** a NuGet package attached to this release: `<QuodCompile Include="Rules\**\*.quod" />` verifies the
  files when the project builds, and a proof that fails makes the build fail, in Visual Studio's error list, with a code
  `QUOD000x`. It is tested in SDK projects on .NET and .NET Framework, and in an old-style project with
  `packages.config`. See [its README](https://github.com/quod-lang/quod/blob/main/packaging/Quod.Build/README.md).
- **`quod build --format msbuild`** and `--output-file`, which it relies on.

## Changed

- **A caller in Python or C# proves nothing, and the public function now says so.** It raises an error for a `requires`
  without quantifier or call (`ValueError` in Python, `ArgumentException` in C#). The others stay the caller's duty, and
  the comment of the function says which. `--check-requires all` checks them too, at their cost; in C#, so does
  defining `QUOD_CHECK_REQUIRES` in the calling project. A generated Python function can therefore raise where it did
  not.
- **`--require-contracts` closes more ways to promise nothing:** a `requires` that fixes a parameter to one value, or a
  sequence to one length, is refused, as is a lemma written as a function.
- **A model that copies the body is reported as a restatement,** like `result == <the body>`.
- **Each `loose` shows what it accepts:** two different results it allows, in the JSON and in the summary
  (`loose: binary_search (xs = [0, 0], target = 0: 1 or 0)`), since no check can tell a freedom that was meant from one that
  gives everything away.

## Measured

- Mutant bench: 57 of 64 mutants refuted, none unconfirmed or without a hint, the 7 survivors equivalent;
  quantified.quod 28 of 29. No verdict changed from 0.1.4.

- **A second correction to the figures of 0.1.3 and 0.1.4.** A contract no tool can decide was counted as not determined.
  [Read one by one](https://github.com/quod-lang/quod/blob/main/bench/runs/t6-haiku/undecided-review.md), and without
  binary_search, the contracts of Haiku that determine the result are 15 of 15 through the shell, 13 of 15 through MCP and
  14 of 15 for Dafny: **no gain measured in how often a contract determines the result.** What the check changes is
  that the verdict is known while the agent writes.
- The six reference solutions pass all their hidden tests through C#, and the programs of the repository give the
  evaluator's results on .NET 10 and on .NET Framework (the 4.8 runtime, targeting 4.7.2).
- [The held-out tasks and their protocol](https://github.com/quod-lang/quod/blob/main/bench/heldout.md) are fixed before
  any run. They will be run on this version.
