Quod 0.2: proved functions for .NET, and a more reliable dialogue with the solver.

0.2 is the C# backend and `Quod.Build`, which came out during 0.1.4 to 0.1.6 without a number of their own, and this change to how sequences reach z3, which changes some verdicts.

## Install

As for [0.1.0](https://github.com/quod-lang/quod/releases/tag/v0.1.0): download the package for
your system, unpack it, and run `quod` from that folder (z3 4.12.1 is inside). On macOS, run
`xattr -d com.apple.quarantine quod z3` in the folder first. The MCP server:
`claude mcp add quod -- /path/to/quod mcp`, or see
[docs/mcp.md](https://github.com/quod-lang/quod/blob/main/docs/mcp.md). `Quod.Build`, attached, is a NuGet package:
see [its README](https://github.com/quod-lang/quod/blob/main/packaging/Quod.Build/README.md).

## Changed

- **Sequences reach z3 as an uninterpreted sort, not its `Seq`.** Quod described sequences by its own axioms already, but the sort alone woke z3's sequence theory. An "unsat" without that theory holds with it. **This changes verdicts:** of 208 Quod programs of this repository, stable over 5 runs each:
  - 197 give the same diagnostics;
  - 2 refused programs are now accepted: an invariant or precondition that timed out is proved;
  - **2 accepted programs are now refused**, both `next_permutation` of the held-out tasks: an assertion times out, and needs help;
  - 7 keep their exit code, with a proof or a completeness that changes status, in both directions.

  The whole set takes 574 s instead of 674 s. A program that spent its time in that theory gains much more: the six `transpose` files went from 3 to 6 s per check to under 1 s per build, and no longer reach a time limit.

## Fixed

- **`--smt-log` is what z3 received**: every command, including those that used to skip it, with the answers and each replacement of z3 as comments, flushed at each line. A test replays a log to the answers it records. The commands of a second z3 (`Fork`) are not in it, and the log says where one starts.

## Measured

- **False "unsat", see [0.1.8](https://github.com/quod-lang/quod/releases/tag/v0.1.8).** With the new sort and without replacing z3, 1000 builds of the `transpose` files gave no false refusal, but none reached a time limit either, so this says nothing on the cause. z3 is still replaced after a timeout.
- **Looking for false proofs, for the first time.** With a time limit of 1 s, on those 208 programs and on the old encoding without replacement, the "unsat" answers that followed a timeout were asked again of a fresh z3, which can only confirm one or fail to. All were confirmed: 280 sampled of 1366 without `--require-contracts`, and 538 of 1367 with it. Of 457 answers with no timeout before them, 2 were not confirmed, and were not examined. **This is a sample and a finite test: with none in 538, the rate of false answers among them can still be up to about 0.6%, and it does not show that no false proof existed.** On the final compiler, 457 of 457 sampled answers were confirmed.
- 177 compiler tests pass.
- Mutant bench: 57 of 64 mutants refuted, none unconfirmed or without a hint, the 7 survivors equivalent, none hung, median time to reject 0.5 s instead of 1.5 s;
  quantified.quod 28 of 29. No verdict changed from 0.1.8.

## Known

- z3 is still 4.12.1. A review saw none of the symptoms with a recent z3, on one file: not measured here.
- Verdicts can still depend on the load of the machine, since time limits are in seconds.
- With no model to read after a timeout, a contract that z3 could have shown underspecified may end as "completeness not decided", a warning.
- If `quod` itself is killed while z3 is busy, z3 can stay behind until it finishes.
