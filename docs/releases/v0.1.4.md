Quod 0.1.4: what a review of 0.1.3 and two local models found.

## Install

As for [0.1.0](https://github.com/quod-lang/quod/releases/tag/v0.1.0): download the package for
your system, unpack it, and run `quod` from that folder (z3 4.12.1 is inside). On macOS, run
`xattr -d com.apple.quarantine quod z3` in the folder first. The MCP server:
`claude mcp add quod -- /path/to/quod mcp`, or see
[docs/mcp.md](https://github.com/quod-lang/quod/blob/main/docs/mcp.md).

## New

- **`--require-contracts`** (`check`, `build`, `mcp`): a function without a contract, or a `loose`
  that accepts every result, is an error, so `verified` means that something was proved about each
  result. It also covers an expression function that no other function calls; those a contract is
  stated with stay allowed. Off by default: without it, these are still warnings. On `quod mcp` it is set on the
  server, and the agent has no argument to turn it off. It asks for a contract, not for the right
  one: `ensures len(result) == 0` with `return [];` still passes.

## Fixed

- **The reference no longer contains a solution.** `quod reference` and `quod_reference` ended with a
  complete binary_search, one of the VerifBench tasks, and agents copied it. They now stop before the
  Python backend, and the shell and MCP arms of the bench read the same text.

## Changed

- **Every Dafny habit of a file that does not parse, in one answer.** The parser stops at its
  first error, and a model fixed one habit per try. The answer now also lists the others found in
  the file: `|s|`, `:=`, `forall i ::`, `var`, `for`, `method`, `let result`, `returns (`, a
  contract clause in a body, an invariant outside a loop, `;` after a clause.
- **An unconfirmed counterexample shows the state the solver assumed.** The inputs alone often
  look harmless; the message now gives the integer and boolean locals: "The solver assumed k = 0,
  s = -1 here, a state no run reaches: the invariant must rule it out".
- **An `exists` the solver cannot prove says what to do:** give it its witness, in a local stated
  in the loop invariant.

## Measured

- Mutant bench: 57 of 64 mutants refuted, none unconfirmed or without a hint, the 7 survivors equivalent;
  quantified.quod 28 of 29. No verdict changed from 0.1.3.

- **A correction to the figures of 0.1.3.** The reference served by `quod_reference` contained a complete
  solution of binary_search, and the MCP agents copied it. Without that task, Haiku's contracts determined are
  14 of 15 through the shell, 9 of 15 through MCP, 9 of 15 for Dafny checked afterwards: through MCP, level
  with Dafny, not ahead.
- Qwen3-Coder 30B with `--require-contracts` in the loop: 5 of 18 accepted, 4 passing all the hidden tests,
  counting as rejected a sixth under `loose (r1, r2) => true`, refused since. The error does not produce the
  contracts it asks for, and one accepted solution is wrong (`ensures result == iv`).

- VerifBench, Qwen3-Coder 30B run locally, three trials of six tasks, without the option: 2 of 18
  solutions verified with a contract, both passing all the hidden tests. Six more verified
  because they state no contract at all, which is why the option exists. Qwen 2.5 Coder 14B, with
  every habit reported at once: 1 of 18 accepted, and that one is wrong (the contract above). It
  is the first escaped bug of these runs. Details in
  [bench/quod](https://github.com/quod-lang/quod/blob/main/bench/quod/README.md#three-trials-dafny-and-another-vendor).
