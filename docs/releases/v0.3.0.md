Quod 0.3: a language for business rules. Modules, strings with a library written in Quod, `i32` and `i64`, structs, enums, `match` and generics.

This is a lot of new code at once, and no agent has written with it yet: treat it as a first version. A program that uses none of it gives the same diagnostics and generated code as 0.2, except where listed below.

## Install

As for [0.1.0](https://github.com/quod-lang/quod/releases/tag/v0.1.0): download the package for
your system, unpack it, and run `quod` from that folder (z3 4.12.1 is inside). On macOS, run
`xattr -d com.apple.quarantine quod z3` in the folder first. The MCP server:
`claude mcp add quod -- /path/to/quod mcp`, or see
[docs/mcp.md](https://github.com/quod-lang/quod/blob/main/docs/mcp.md). `Quod.Build`, attached, is a NuGet package:
see [its README](https://github.com/quod-lang/quod/blob/main/packaging/Quod.Build/README.md).

## New

```rust
import strings

struct Candidate {
  value: string,
  confidence: i32,
}

enum Decision {
  Accepted(value: string),
  Rejected(reason: string),
}

fn decide(c: Candidate, keep: i32) -> Decision
  ensures match result {
    Accepted(v) => v == strings.trim(c.value) && c.confidence >= keep,
    Rejected(r) => r == "too low" && c.confidence < keep,
  }
{
  if c.confidence >= keep { Accepted(strings.trim(c.value)) } else { Rejected("too low") }
}
```

- **Modules.** A file is a module. `import name`; a function of another module always has its full name; `private fn`. Everything imported is verified with the program, every time.
- **`char` and `string`.** A string is a sequence of Unicode scalar values, the same in every backend. Nothing is normalized, and nothing depends on a locale.
- **A standard library in Quod,** proved with your program: `import strings` and `import option`.
- **`i32` and `i64`.** In code, an operation that leaves the bounds is a proof not met, with a counterexample. In contracts, arithmetic is mathematical. In C#, they are `int` and `long`.
- **`struct`, `enum`, `match`.** A `match` covers every case. In C#, immutable classes equal by value, with `IEquatable<T>`, `==` and a hash on what they hold, which copy the lists they are given and hand out views that cannot be cast back; an enum has a `Match` with one function per case, so a C# caller can be held to every case too. In Python, frozen dataclasses.
- **Generics,** by copies: a generic function is checked and proved for the types it is used with. A type cannot hold itself: no recursive types yet.
- **`run_by`:** contracts read a definition by recursion, and code runs a loop proved equal.
- **A tail call runs as a loop,** in Python and in C#, in an `if`, a `&&`, a `||` or a `match`, whatever the length of the input.

[The reference](https://github.com/quod-lang/quod/blob/main/spec/quod-0.1.md) describes them all.

## Changed

- An expression function that ends by calling itself is generated as a loop, so its generated code changes, not its verdict. A stack overflow on a deep input no longer happens for it.
- A C# method whose name would be that of a type gets `Of`, and a double underscore in a function's name keeps an underscore in its C# name.

## Measured

- 224 compiler tests pass.
- Mutant bench: 57 of 64 mutants refuted, none unconfirmed or without a hint, the 7 survivors equivalent, none hung; quantified.quod 28 of 29. No verdict changed from 0.1.8, the last run of this bench before this version.
- **On the library:** 39 of 40 mutants of `strings.quod` refuted with a counterexample, the last rejected without one, none survived.
- On 42 programs of this repository written before these features, compared with 0.2.0: the same exit codes and generated code; 2 differ in the wording of one diagnostic, a proof given up on its time limit. This comparison came before the tail calls.
- Python and C# on .NET Framework 4.7.2 gave the same answers on hand-written programs: accents, combining accents, emoji, lone surrogates refused, overflows at the bounds, Euclidean division, three modules, generics.
- **An outside review of this version** ran 4750 cases through the evaluator, Python and C# (on .NET 10) on the new types, with no difference, and tried to break the rules. It found **two false proofs and a generated program that contradicted a proof**, all fixed here, with their programs as tests: a fact on the length of every sequence, which also held for `xs + xs` and so proved `len(xs) <= 2^30`; a `run_by` that could require more than the function it runs for; and `int.MinValue % -1`, which throws in .NET. That three such faults took one session says how much this new code had been attacked before: little.

## Known

- **No measure with agents.** Whether an agent writes these features well, and whether `i32` costs it too many proofs, is not known.
- **Copies of generics are verbose in C#:** `Option.Option_int.Some`, whose field is `F0`, and a `BigInteger` for Quod's `int`. For C#, prefer `i32` and `i64` in signatures.
- **A C# caller is not forced to use `Match`:** it can still test the classes itself.
- **Python:** the elements of a `seq<i32>` are checked only with `--check-requires all`, and that a list received has at most 2^31 - 1 elements is assumed. A frozen dataclass copies the lists it is given, but still hands out one that a caller could change.
- **A recursion that is not a tail call** follows its input in depth, in the generated code: use `run_by`. In the library, `digits_value` and `digits_of` remain so, which their inputs make harmless.
- A generic function is not checked at all until it is used, and a warning says so.
- A contract that calls itself through another function, rather than directly, can still crash the compiler.
- Everything of 0.2 still holds: z3 is 4.12.1, and verdicts can depend on the load of the machine.
- **There may be other false proofs in this new code.** They were looked for during one session of review, and two were found.
