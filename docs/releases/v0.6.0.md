Quod 0.6.0: the console, as a capability. A program can now write, and a contract says what it writes. Nothing changes for a program that does not import `console`.

## Install

As for [0.1.0](https://github.com/quod-lang/quod/releases/tag/v0.1.0): download the package for
your system, unpack it, and run `quod` from that folder (z3 4.12.1 is inside). On macOS, run
`xattr -d com.apple.quarantine quod z3` in the folder first. The MCP server:
`claude mcp add quod -- /path/to/quod mcp`, or see
[docs/mcp.md](https://github.com/quod-lang/quod/blob/main/docs/mcp.md). `Quod.Build`, attached, is a NuGet package:
see [its README](https://github.com/quod-lang/quod/blob/main/packaging/Quod.Build/README.md).

## A program

```rust
import console

fn main(c: console.Console) -> console.Console
  ensures console.written(result) == console.written(c) + ["Hello from Quod", "this line was proved"]
{
  let a = console.say(c, "Hello from Quod");
  console.say(a, "this line was proved")
}
```

`quod run hello.quod` checks the file, then runs `main` and prints the two lines.

## Added

- **The `console` module of the standard library.** `console.Console` is a *capability*: a function writes only through a `Console` it receives, so a function that has none among its parameters cannot write, and its signature says so. `console.say(c, line)` writes the line and returns the next `Console`. In a contract, `console.written(c)` is the sequence of the lines written so far, and `say` is specified by it: `written(result) == written(c) + [line]`. The proofs rest on that model; the real console is not verified.
- **A `Console` is used once.** `let d = console.say(c, "a")` consumes `c`, and naming `c` again is an error: otherwise `written(c)` would speak of a console that no longer exists, and the proof would be false. Each branch of an `if` or a `match` may use it; a loop that uses one must end each turn by assigning the one it went on with (`d = console.say(d, ...)`). A program cannot build a `Console`, read its lines in code, or keep one in a sequence, a map, a set, a field or a type argument; it passes it on or returns it, alone or in a tuple.
- **The completeness check covers what is written.** A contract that says only how many lines a function writes is refused, as one that says only the length of a result is: `ensures len(console.written(result)) == len(console.written(c)) + 1` accepts any line.
- **`quod run file.quod [--function NAME]`** checks the program, then runs `main(c: console.Console) -> console.Console` with the evaluator and prints the lines written, at the end of the run. It needs neither Python nor .NET.
- **`quod_run`** (MCP) takes a console as the array of lines already written (`[]` for a new one) and returns the lines.
- **Python:** `console.Console()` writes to the standard output, `console.Console(stream)` to any text stream (a test gives an `io.StringIO`); `console.say` returns the same object. **C#:** `new ConsoleModule.Console()` or `new ConsoleModule.Console(textWriter)`; `ConsoleModule.Say` returns the same object. The module is written by Quod next to the generated files, not generated from `console.quod`.

## Fixed

- **A proof with a string literal of 12 characters or more could take 25 seconds or give up.** A literal was a chain of concatenations, one per character, and the solver unfolded them all when two lines were compared (`written(result) == written(c) + [a, b]`). A long literal is now a constant of the proof, with its length and its characters: the same proof takes a second. This applies to every program with long strings, not only to the console. Short literals are unchanged.

## Known

- **Output only.** No reading, no files, no network yet: reading comes next, then files (the model of a file system will be a `map<string, string>`).
- **`quod run` runs the program with the evaluator**, which is slow on big loops, and prints the lines when the run ends, not as they are written. The generated Python and C# write as they go.
- **The model of the console is a list of lines.** It says nothing of a console that fails (a closed pipe), of two processes writing together, or of the encoding of the output.
- **Without the sugar of a `mut` parameter, a program that writes much repeats `let c2 = ...`**; whether to add it will be decided on programs written with this form.
- **No agent has written a program with a console yet**: whether the rule of use-once costs agents anything is not measured.
- The `Console` of the C# module is a class over a `TextWriter`, not an interface; a test substitutes a `StringWriter`.
- Sealed contracts and general refinement types, announced for 0.6, move to 0.7.

## Measured

- 282 tests pass, among them 11 on the console and 2 on long literals.
- Mutants, on a Release build (15 per file, a larger sample than in 0.5, so the counts are not comparable): the reference programs, 81 refuted of 88 (2 rejected without a hint, 5 survived); the quantified `requires`, 13 of 15; the dictionaries, 11 of 11. The two rejected without a hint (`merge_intervals`, 13 and 17 s) give the same verdict on 0.5.0: they are not new. Slowest check to reject a mutant: 107 s (a program of the bench, on a build that is not AOT).
