Quod 0.4.2: a failed loop invariant is named by its text, not only by its number.

## Install

As for [0.1.0](https://github.com/quod-lang/quod/releases/tag/v0.1.0): download the package for
your system, unpack it, and run `quod` from that folder (z3 4.12.1 is inside). On macOS, run
`xattr -d com.apple.quarantine quod z3` in the folder first. The MCP server:
`claude mcp add quod -- /path/to/quod mcp`, or see
[docs/mcp.md](https://github.com/quod-lang/quod/blob/main/docs/mcp.md). `Quod.Build`, attached, is a NuGet package:
see [its README](https://github.com/quod-lang/quod/blob/main/packaging/Quod.Build/README.md).

## Changed

- **The message of a failed invariant shows the invariant.** A newcomer who ran `max_index_bug.quod` read "invariant #1 is preserved by the loop body" and had to count lines to find which one. The message is now
  `invariant #1 `1 <= i && i <= len(xs)` is preserved by the loop body`, in the verifier and in the evaluator that finds counterexamples by running the function. The number stays, so a message is still found by its start. The JSON field `property` carries the longer text.

Nothing else changes: the verifier, the proofs and the generated code are those of 0.4.1.

## Around the release (not part of the package)
